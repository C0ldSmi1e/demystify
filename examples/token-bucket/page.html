A token bucket passes a burst of up to 20 requests, then 5 requests each second, by default

Each request takes one token from a bucket. By default, the bucket starts full with 20 tokens and earns 5.0 tokens each second. If the bucket holds less than one token, handle() rejects the request with status 429 and a Retry-After header.

The picture

Step by step

  1. 1. The bucket starts full

    A new bucket holds capacity tokens: 20 by default. Thus the first requests pass immediately. This is the burst.

  2. 2. Tokens come back with time

    No timer runs. Before each decision, _refill() adds the seconds since the last call × refill_rate: 5.0 by default. The bucket never holds more than capacity.

  3. 3. A request arrives

    handle() calls allow() one time for each request. The default cost of a request is 1 token.

  4. 4. The bucket decides

    If the bucket holds 1 token or more, allow() takes 1 token and returns True. If not, it takes nothing and returns False.

  5. 5. Yes: the handler gets the request

    handle() passes the request to the handler. It returns the answer of the handler.

  6. 6. No: the caller gets a 429

    handle() returns status 429 and a Retry-After header. The header gives the seconds until the bucket holds 1 token, with one decimal place.

Try it

The model sends requests at equal intervals for 10 seconds. It uses the same rule as the source, with a simulated clock.

Limits

  • The model sends requests at equal intervals, each with a cost of 1 token. Real requests do not arrive at equal intervals. By default, the source reads the time from time.monotonic.
  • One TokenBucket object is one limit for all the requests that use it. The source does not show a bucket for each client.
  • Tested: The model of this page and the Python source gave the same result for each request, for all 32,000 settings of the three sliders.
  • Tested: Float arithmetic can reject a request at an exact limit. In the default example, exact arithmetic gives 1 token at 3.8 s. The source holds a little less than 1 token, rejects the request, and writes Retry-After: 0.0.
  • Tested: If cost is larger than capacity, allow() never returns True. On a full default bucket, retry_after(21) returns 0.2, also after 1000 seconds.
  • Inferred: The class has no lock. Two threads that use one bucket at the same time can get incorrect token counts.
  • General knowledge: The HTTP standard (RFC 9110) defines Retry-After as a date or a whole number of seconds. The source writes one decimal place. Not verified: how HTTP clients read a value such as 0.2.

Terms

Token
The permission for one request. It is a number in the bucket, and the number can have a fraction.
Capacity
The largest number of tokens that the bucket holds. It is also the largest burst.
Burst
Requests that arrive together and pass, because the bucket has tokens for them.
Refill rate
The tokens that the bucket earns each second. It is the rate that the limiter permits for a long time.
429
The HTTP status "Too Many Requests".
Retry-After
The header that tells the caller how many seconds to wait.
